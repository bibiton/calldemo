# 05 — 前端應用

## 0. 共通規範

- React + Vite + Tailwind；每個 app 是獨立 Pages 專案、獨立子網域。
- **手機直版優先（mobile-first、portrait）**：總後台、門店後台、人員端、顧客頁都必須在 **360×640 直立手機**完整可用。
  桌機只是同一版面放寬（`md:` 以上變雙欄、表格展開更多欄），**不另做桌機版**。
- 叫號面板（display）以**直立電視**為主（1080×1920），橫式只做「可用」不做最佳化。
- 表格在手機上改「卡片列表」；主要操作按鈕固定在畫面底部（拇指可及）。
- 觸控目標 ≥ 44×44 px；字級 ≥ 16 px（避免 iOS 輸入框自動放大）。
- 共用：`packages/shared`（WS client、型別、遮罩、手機驗證、QR token 演算法）。

### QR 區規格

- 位置：右下角，`position: fixed`，`z-index` 高於廣告層；廣告區的版面排除此區（不是疊上去）。
- 尺寸：**QR 本體邊長 ≥ 螢幕寬度的 38%**。55 吋直立電視寬約 68 cm → QR 約 26 cm，
  依「掃描距離 ≈ 10 × QR 邊長」的經驗比例，可在約 2.5 公尺掃到。（比例為經驗值，**實機驗證列在 roadmap**）
- QR 內容盡量短（`https://q.<domain>/s/<code>?w=<n>&k=<10字>`），使用 QR Version ≤ 4、糾錯 M → 模組大、好掃。
- 黑白高對比、四周留白 ≥ 4 模組；下方一行「**掃碼取號**」（≥ 48 px）。
- 每 120 秒換一張（ADR-012），切換前 5 秒預算好，不閃白。
- 門店停用／休息中：QR 區改顯示「暫停取號」，不顯示可掃的 QR。

### 叫號播放（ADR-003、ADR-017）

順序：**叮咚音效 → 叫號句（前綴＋號碼＋櫃台，例：「等到肚子餓的來賓，A23 號，請到 2 號櫃台」；標準版前綴為「來賓」）× N 次（預設 2）→（可選）趣味穿插語句 → 廣告恢復**。

- 前綴：依門店設定的主題包／單句與出現機率，從 manifest 中隨機挑選原創俏皮前綴；未命中機率或關閉時用標準「來賓」。同一號碼重複唸的 N 次使用同一前綴。

- 播放佇列：多筆叫號依序播放、**不重疊**；`recall` 一樣進佇列播放（重叫不插趣味語句）。同一號碼在佇列中重複出現時合併為一次。
- 叫號期間：廣告影片 `muted = true` 並暫停（`pause()`）；佇列清空後恢復播放（影片從暫停處繼續）。圖片輪播計時器同樣暫停。
- 語音：**全部預錄**（業主定案，edge-tts 產生，親切俏皮風格、台詞原創），依 `assets/audio/manifest.json` 找片段，
  以 Web Audio API 依序排程、無縫拼接。不做即時語音合成。
- 語音包隨 `apps/display` 靜態部署（ADR-026），由 Service Worker 漸進快取（見 07-notifications §7），之後斷網照樣能唸。
- 只有在素材缺檔／解碼失敗時才退回 `speechSynthesis` 唸基本句型（最後備援），並提示店長素材不完整。
- 門店後台可設定：音量、唸幾次（1～3）、叮咚音效款式、語言（MVP 中文）、靜音時段、**趣味語音開關與頻率**，經 `settings.changed` 下發。

### 啟用聲音（瀏覽器自動播放限制）

- 首次配對或每次開機後，若 `AudioContext.state !== "running"`，全螢幕顯示覆蓋層
  「**請點一下畫面啟用聲音**」（大字、閃爍邊框），點擊後解鎖並播放一次叮咚確認。
- 解鎖前 QR 與號碼照常顯示；收到叫號事件時覆蓋層變紅提醒店員。
- Kiosk 裝置免點擊設定（參考，**未逐一實機驗證**）：
  - Android 電視盒 Chrome：啟動參數 `--autoplay-policy=no-user-gesture-required`（需可自訂啟動參數的 kiosk launcher）
  - Fully Kiosk Browser：設定中的自動播放影片／允許音訊不需互動選項
  - Chromium（Linux／Windows 迷你電腦）：`chromium --kiosk --autoplay-policy=no-user-gesture-required https://display.<domain>`

### 廣告輪播（ADR-016）

- 素材：圖片（JPEG/PNG/WebP，≤ 5 MB）、影片（**MP4 H.264**、建議 1080×1920 直式、**≤ 50 MB**、≤ 120 秒）。
- manifest：`GET /api/display/ads/manifest` → `{version, items:[{assetId,url,kind,durationMs,activeFrom,activeTo,dows,startDate,endDate}]}`；
  `url` 指向 `media.<domain>/ads/<owner>/<sha256>.<ext>`（內容不可變，可長期快取）。
- 面板收到 `ads.manifest{version}` 且版本比本地新 → 重抓 manifest → Service Worker 下載新素材、刪除不再使用的。
- **播過一次就不再下載**：素材存在 Cache Storage；斷網時繼續播放快取中的素材並顯示最後狀態。
- 品牌統一下發：manifest 合併品牌清單（若門店 `accept_brand=1`）與門店清單。

### 其他

- 配對頁：顯示 6 位數配對碼與 QR（讓店長用手機掃碼完成配對），10 分鐘有效。
- 斷線時頂欄顯示小型「連線中…」，不清空畫面。
- 休息中畫面：Logo＋營業時間，廣告照播（可在設定關閉）。

## 2. 顧客取號頁 `apps/customer`

入口只有一個：**掃叫號面板上的動態 QR**。（不使用固定貼紙 QR，避免網址外流造成遠端灌號。）

### 流程（3 步）

```
① 掃碼 → 頁面載入時驗證 token，取得取號 session
┌──────────────────────┐
│ [Logo] 門店名稱        │
│ 請選擇服務            │
│ ┌──────────────────┐ │
│ │ A 一般櫃台  等 12 │ │
│ └──────────────────┘ │
│ ┌──────────────────┐ │
│ │ B 繳費      等 3  │ │
│ └──────────────────┘ │
└──────────────────────┘
② 填資料
┌──────────────────────┐
│ 姓名  [王小明      ]  │
│ 手機  [0912345678  ]  │  ← inputmode="tel"，即時驗證 ^09\d{8}$
│ ☐ 我同意個資使用說明  │  ← 點開顯示全文（必勾）
│   （目的：叫號與現場聯繫；│
│    原文當日營業結束刪除）│
│                      │
│ [   開啟提醒並取號   ] │  ← 底部固定；同一次點擊請求通知權限＋解鎖音效
└──────────────────────┘
③ 號碼頁
┌──────────────────────┐
│     您的號碼          │
│      A 0 2 3          │
│  前面還有 5 位        │
│  預估約 12 分鐘        │
│ ──────────────────── │
│ 🔔 提醒已開啟          │
│ 請保持此頁開啟，或     │
│ 加入主畫面以接收提醒   │  ← iOS 且非 standalone 時顯示教學
│ ──────────────────── │
│ [取消號碼]            │
└──────────────────────┘
```

- 手機格式：接受 `0912-345-678`、`+886912345678`，正規化為 `0912345678` 後驗證 `^09\d{8}$`。
- 姓名：去除前後空白，1～20 字。
- **防重複**：同店同手機已有進行中號碼 → 姓名相符則直接帶到原號碼頁（顯示「您已有號碼」）；
  姓名不符則顯示「此手機已有進行中號碼，請洽櫃台」。
- 號碼頁 ticket token 存 localStorage；重新掃碼或重開頁面直接回到號碼頁。
- 叫到號：頁面在前景 → 全螢幕紅底大字＋響鈴＋`navigator.vibrate`（iOS Safari 不支援震動，以聲音與畫面閃爍代替）；
  頁面在背景 → Web Push。
- 叫號後未到：顯示「已過號，請洽櫃台」。

```
┌──────────────────────┐
│ 廣告管理   已用 182/500MB│
│ ████████░░░░░░░░░░    │
├──────────────────────┤
│ ≡ [縮圖] 夏季促銷.mp4  │
│    32秒 · 全天 · 啟用 ●│
│ ≡ [縮圖] 新品.jpg      │

└──────────────────────┘
```

- 上傳流程：前端檢查（MIME、大小、`<video>` 讀 metadata 取寬高與長度）→ `POST /api/store/ads/uploads` 取得一次性上傳 URL
  （Worker 檢查容量配額）→ 直接 PUT 到 Worker 串流寫入 R2 → 完成後寫 `ad_assets`（`bytes` 進用量計算）→ playlist `version + 1` → DO 廣播 `ads.manifest`。
- 不做伺服器端轉檔（不用 Stream）；不符規格直接在前端擋下並說明原因。
